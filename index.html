API Information

Base URL

https://dear-nobody-api-production.up.railway.app

Authentication

Protected endpoints require a JWT token. 

Authorization: Bearer YOUR_TOKEN

The JWT token is returned from POST /login.

1. Sign Up

POST /signup

Request


{
"username": "Alice",
"email": "[alice@example.com](mailto:alice@example.com)",
"password": "123456"
}

Expected Result

Creates a new user and stores the password securely as a hashed password.

Example Response



{
"message": "User created successfully",
"user": {
"id": 1,
"username": "Alice",
"email": "[alice@example.com](mailto:alice@example.com)",
"created_at": "2026-10-05T10:00:00.000Z"
}
}

Error Example



{
"error": "Username or email already exists"
}

Status: 400 Bad Request

2. Log In

POST /login

Request



{
"email": "[alice@example.com](mailto:alice@example.com)",
"password": "123456"
}

Expected Result

Verifies the user's email and password and returns a JWT authentication token.

Example Response



{
"message": "Login successful",
"token": "YOUR_JWT_TOKEN"
}

Error Example



{
"error": "Invalid email or password"
}

Status: 401 Unauthorized

3. Get Users

GET /users

Request

No request body is required.

Authentication header: 

Authorization: Bearer YOUR_TOKEN

Expected Result

Returns registered users except the currently authenticated user. The response also shows the friendship status and direction between the authenticated user and each user.

Example Response



[
{
"id": 2,
"username": "Bob",
"email": "[bob@example.com](mailto:bob@example.com)",
"created_at": "2026-10-05T10:05:00.000Z",
"friendship_id": 1,
"friendship_status": "pending",
"friendship_direction": "outgoing"
},
{
"id": 3,
"username": "Charlie",
"email": "[charlie@example.com](mailto:charlie@example.com)",
"created_at": "2026-10-05T10:10:00.000Z",
"friendship_id": 2,
"friendship_status": "accepted",
"friendship_direction": "incoming"
},
{
"id": 4,
"username": "David",
"email": "[david@example.com](mailto:david@example.com)",
"created_at": "2026-10-05T10:15:00.000Z",
"friendship_id": null,
"friendship_status": null,
"friendship_direction": null
}
]

Friendship Status

  • pending - Friend request has not been accepted yet
  • accepted - Friendship has been accepted
  • null - No friendship request exists

Friendship Direction

  • outgoing - You sent the friend request
  • incoming - The other user sent the friend request
  • null - No friendship request exists

Error Example



{
"error": "Authentication token is required"
}

Status: 401 Unauthorized

4. Send Friend Request

POST /friends

Request

Authentication header: 

Authorization: Bearer YOUR_TOKEN

Request body:



{
"friend_id": 2
}

Expected Result

Creates a pending friend request from the authenticated user to the selected user.

Example Response



{
"message": "Friend request sent",
"friendship": {
"id": 1,
"user_id": 1,
"friend_id": 2,
"status": "pending"
}
}

Error Example



{
"error": "Friend ID is required"
}

Status: 400 Bad Request

Another Error Example



{
"error": "You cannot add yourself as a friend"
}

Status: 400 Bad Request

Another Error Example



{
"error": "Friend not found"
}

Status: 404 Not Found

Another Error Example



{
"error": "Friendship already exists"
}

Status: 400 Bad Request

5. Accept Friend Request

PUT /friends/:id

Request

Replace :id with the friendship ID.

Example: 

PUT /friends/1

Authentication header: 

Authorization: Bearer YOUR_TOKEN

No request body is required.

Expected Result

Accepts a pending friend request where the authenticated user is the recipient of the request.

Example Response



{
"message": "Friend request accepted",
"friendship": {
"id": 1,
"user_id": 1,
"friend_id": 2,
"status": "accepted"
}
}

Error Example



{
"error": "Friend request not found"
}

Status: 404 Not Found

6. Create Post

POST /posts

Request

Authentication header: 

Authorization: Bearer YOUR_TOKEN

Request body:



{
"content": "Hello from Dear Nobody!",
"visibility": "public"
}

Visibility options:

  • public
  • friends

Expected Result

Creates a new post for the authenticated user.

Example Response



{
"message": "Post created successfully",
"post": {
"id": 1,
"user_id": 1,
"content": "Hello from Dear Nobody!",
"visibility": "public",
"created_at": "2026-10-05T10:15:00.000Z"
}
}

Error Example



{
"error": "Content and visibility are required"
}

Status: 400 Bad Request

Another Error Example



{
"error": "Visibility must be Public or Friends-only"
}

Status: 400 Bad Request

7. Get Posts

GET /posts

Request

No request body is required.

Authentication header: 

Authorization: Bearer YOUR_TOKEN

Expected Result

Returns:

  • Public posts from all users
  • Your own posts
  • Friends-only posts from accepted friends

Posts are returned in ascending order by creation time.

Example Response



[
{
"id": 1,
"user_id": 1,
"content": "This is my post.",
"visibility": "public",
"created_at": "2026-10-05T10:15:00.000Z",
"username": "Alice"
},
{
"id": 2,
"user_id": 2,
"content": "Hello everyone!",
"visibility": "public",
"created_at": "2026-10-05T10:20:00.000Z",
"username": "Bob"
},
{
"id": 3,
"user_id": 2,
"content": "This is my friends-only post.",
"visibility": "friends",
"created_at": "2026-10-05T10:25:00.000Z",
"username": "Bob"
}
]

Error Example



{
"error": "Authentication token is required"
}

Status: 401 Unauthorized

Post Visibility

public

A public post can be seen by all authenticated users.

friends

A friends post can be seen by the post owner and users who have an accepted friendship with the post owner.

Friend Request Flow

  1. User A sends a friend request to User B.
  2. The friendship is created with status pending.
  3. User B sees the request as an incoming request.
  4. User B accepts the request using PUT /friends/:id.
  5. The friendship status changes to accepted.
  6. Both users can now see each other's friends-only posts.
